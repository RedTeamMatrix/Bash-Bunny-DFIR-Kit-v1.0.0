# Security Policy

## Supported scope

This project documents a **defensive DFIR triage workflow**. The public repo contains documentation and public-safe helpers. Operational payloads are dual-use and distributed separately with controls.

## Responsible disclosure (vulnerabilities)

If you discover a security issue in this repository (e.g., a leaked secret, a vulnerable example, or a documentation error that meaningfully increases abuse risk):

1. **Do not open a public issue.**
2. Email the maintainer: **<your-email@example.com>** (preferred), or use GitHub Security Advisories if enabled.
3. Provide:
   - A clear description of the issue and impact
   - Steps to reproduce (if applicable)
   - Suggested remediation

We will acknowledge receipt within **5 business days** and aim to publish a remediation or plan within **14 days**.

## Reporting abuse / misuse

If you see this project or its materials used for **unauthorized access or offensive activity**, please report:
- The location (URL/repo)
- A brief description of the misuse
- Any involved artifacts (screenshots, hashes)

Email **<your-email@example.com>**.

## Defensive use only

This project is intended for **authorized Digital Forensics & Incident Response**. By downloading or using any associated artifacts you agree to:
- Use only on systems you are authorized to access.
- Comply with applicable laws, contracts, and policies.
- Preserve chain-of-custody where applicable.

We do **not** provide support for offensive or unauthorized use. Submissions that materially lower abuse barriers (e.g., exploit PoCs, auto-elevation HID payloads) will be rejected and may be removed.

## Secrets & sensitive data

Do not submit:
- Credentials, tokens, or private keys
- Real case data or PII
- Internal hostnames, IPs, or screenshots containing sensitive info

If you accidentally commit sensitive data, contact us immediately so we can coordinate removal and revocation.
